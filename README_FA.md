# بسته آزمایشی سرور و پایگاه داده — سامانه پایش قرارگاه جنگ اقتصادی

این بسته برای **آزمایش با داده‌های کاملاً ساختگی** طراحی شده است. شامل Flask، PostgreSQL، ورود مدیر آزمایشی و API ثبت/مشاهده/ویرایش/حذف گزارش‌هاست. این نسخه تأیید امنیتی یا مناسب اطلاعات سازمانی واقعی نیست.

## استقرار روی Render با Blueprint

1. محتویات این پوشه را در ریشه مخزن GitHub با نام `qarargah-payesh` قرار دهید (فایل `index.html` باید در ریشه مخزن باشد).
2. در Render از منوی **New** گزینه **Blueprint** را انتخاب کنید و مخزن `qarargah-payesh` را متصل کنید.
3. Render فایل `render.yaml` را می‌خواند و یک Web Service و یک PostgreSQL آزمایشی می‌سازد.
4. در مرحله تأیید Blueprint، برای `ADMIN_PASSWORD` یک رمز آزمایشی قوی و منحصربه‌فرد وارد کنید. رمز را در GitHub یا چت قرار ندهید.
5. تأیید استقرار را انجام دهید. پس از پایان، URL سرویس `qarargah-payesh-server.onrender.com` خواهد بود.
6. برای ورود، نام کاربری `demo-admin` و همان رمز آزمایشی تعیین‌شده را استفاده کنید.

## API

- `GET /api/health` بررسی اتصال پایگاه داده
- `POST /api/login` ورود مدیر آزمایشی
- `POST /api/logout` خروج
- `GET /api/records` فهرست گزارش‌ها (پس از ورود)
- `POST /api/records` ثبت گزارش
- `PUT /api/records/<id>` ویرایش گزارش
- `DELETE /api/records/<id>` حذف گزارش

## محدودیت‌ها

- طرح دیتابیس عمومی و ساده است؛ هر گزارش در دسته‌بندی و payload JSON ذخیره می‌شود.
- فقط یک حساب مدیر آزمایشی از طریق متغیرهای محیطی وجود دارد؛ مدیریت چندکاربره و نقش‌های سازمانی پیاده‌سازی نشده است.
- نسخه رایگان Render ممکن است محدودیت منابع، خواب سرویس یا انقضای دیتابیس آزمایشی داشته باشد؛ برای داده مهم مناسب نیست.
- داده واقعی، شخصی، محرمانه یا حساس وارد نکنید. برای بهره‌برداری واقعی باید میزبانی مجاز، احراز هویت چندعاملی، کنترل دسترسی، ثبت رخداد، پشتیبان‌گیری و بازبینی امنیتی اضافه شود.
